## 조류계산 실행법 (중요)

```
python codes\powerflow\powerflow.py data
```
**플래그 없이 한 번에 결정론적으로 수렴**합니다(계통모선 0.946~1.052pu, FACTS·발전기 무효한계 준수, 손실 ~2.19GW). 이는 모델이 `freeze_operating_point.py`로 **운전점이 구워진 풀린 스냅샷**이기 때문입니다(실제 PSS/E 풀린 케이스와 동일):
- **OLTC 탭**: 154/22.9·345/154 변압기의 운전탭이 `trafo2w.ratio`/`trafo3w.ratio_mv`에 기록됨(중립 1.0이 아님).
- **발전기**: 운전점 단자전압을 `vset_pu`로, `reg_bus=0`(로컬 PV) — 원격제어(IREG) 외부루프 제거.
- **모선 전압**: `bus.vm_pu`/`va_deg`에 풀린 해 기록(스냅샷).

⚠️ **`--oltc --shunt-control`을 주지 마세요.** 그러면 이미 구워진 탭 위에 active OLTC 컨트롤러가 다시 동작해 이중제어가 되고, 그 외부루프는 PYTHONHASHSEED에 따라 결과가 흔들립니다(과거 0.82~0.97로 비결정론적이던 원인). 운전점은 이미 고정돼 있으니 plain 실행이 정답입니다.

⚠️ 운전점은 **85GW 중부하 스냅샷** 기준입니다(어떤 스냅샷 케이스나 동일). 부하·디스패치를 크게 바꾸면 `freeze_operating_point.py`로 다시 풀어야 합니다. 빌드(`build_model.py`)는 미-freeze 모델(탭 1.0·IREG)을 내므로 **빌드 후 반드시 freeze 단계**를 거쳐야 합니다.

## HVDC (dcline.csv / vscdcline.csv)

별도 세션에서 powerflow.py에 구현된 **컨버터 모델**(2단자 LCC + VSC)용 파일. 컨버터 파라미터(브리지 수·점호각·환산리액턴스·필터 등)는 해당 세션 산출값 그대로이며, **모선번호만 v2 번호체계로 재해석**(build_model.py §9b가 이름→번호 해석으로 직접 생성하므로 재빌드에도 항상 정합 — v1 번호를 그대로 두면 다른 변전소에 연결되는 silent corruption이 생겨 재매핑이 필수였음). 로더 규약: dcline이 있으면 동일 모선쌍의 `HVDC_*` AC 등가선을 in_service=False로 자동 대체(supersede) — dcline 파일을 지우면 레거시 AC 등가 거동으로 복귀. 노브 `KM_DC_MODEL=0`이면 빌드가 dc 파일을 생성하지 않음. 검증: 4링크 모델링·AC 4선 대체·전송 1,285MW·수렴 확인(2026-06-12).

⚠️ 북당진-고덕 `setvl`(-1,040.6MW)은 구모델 자연조류를 답습한 값 — 실설비는 1.5~3GW 스케줄 운전(KPG-193 dcline은 1,500MW)이므로 수도권 융통 시나리오에서는 setvl 상향을 권장.

dcline 활성화로 본토 변환소 권역(전남 서남해안)에 LCC 정류기 순무효소비가 더해져 fringe 저전압이 노출됨 → **표적 SC 8기 225Mvar 추가**(`SC_HVDC_FRINGE`, EPSIS 광주전남 SC 1,120Mvar 대비 모델 720Mvar로 한도 내 — 지역 정합 개선). 잔여: **진도 코너 5모선 0.92~0.95**(진도_D23 0.921, 화원·안좌·진도변환소 0.943~0.949) — 도서 radial 말단+정류기 무효소비로, SC 증액 시도는 스위치드샨트/OLTC 제어 정착이 흔들려 역효과(코드 주석 참조). 실계통도 본 권역은 보상설비 집중 지역임을 감안해 한계로 문서화.
